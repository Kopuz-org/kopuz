# Kopuz v2: the spec

v1 of this fork is a faithful port of the Dioxus app, and the Dioxus app is a
database browser with a play button: fourteen flat pages, one per table,
mouse-first, four player surfaces that disagree with each other. v2 stops
porting and starts designing.

**The identity:** the fast, keyboard-driven, native music player. Everything a
webview cannot be. The audience runs a Rust daemon against Jellyfin or YouTube
Music on Linux; they are power users, and GPUI is the framework Zed is built
on. Dense, instant, driveable without a mouse.

`docs/PARITY.md` stays the feature checklist: nothing the original does is
lost. `docs/UX.md` is the defect list; its open items are folded in below.
`docs/STYLING.md` stays the law on colour, spacing and motion.

Work packages are sized for one agent each. **Each names the crates it owns;
touch nothing else.** The dependency graph is at the end.

---

## 0. Rules every agent works under

**House rules (enforced, no exceptions)**
- Comments: hard limit ONE line. No multi-line comment blocks, no multi-line
  doc comments. Default to none; write one only for a non-obvious *why*.
- Never create an issue or a PR. Do not commit unless told to; leave work in
  the tree. If told to commit: identity `umceko <umutcevdetkocak@gmail.com>`,
  scope `crate/module:` or `various:`, subject ≤ 80 chars, no AI references.
- `sed` and `python` may be denied as shell tools; use Read/Edit/Write + awk.
  In awk replacement strings `&` means "the match": never write one, use Edit.
- Everything runs through nix: `nix develop --command cargo …`.
- The gate, before reporting done:
  `cargo fmt --all` · `cargo clippy --workspace --all-targets -- -D warnings` ·
  `cargo test --workspace -j 4` · the route smoke (`KOPUZ_ROUTE=<page>`, one
  process per route, no "panicked" in the log).

**i18n:** the locale files live in `apps/common/i18n/
locales/` (28 files). CI requires key parity with `en.ftl`, not translation.
A new string means: add the key to `en.ftl`, and add the same key with the
English text to the other 27. Never hardcode a user-visible string. Never
render a raw key. Prefer an existing key when one says the same thing.

**GPUI traps this port has already paid for. Read before writing UI.**
1. `.hover(|s| …)` on a `Button` panics on render (`debug_assert!("hover style
   already set")`). A Button's colours come from its variant.
2. A Button with BOTH `.tooltip()` and `.on_hover()` panics: the tooltip
   installs its own `on_hover` and an element takes one. Put the hover on a
   wrapper div.
3. Instance `.bg()/.text_color()/.border_color()` on a Button is overpainted
   while hovered, and `.ghost()`/`.text()` hardcode the hovered foreground.
   Use `style::button / quiet_button / bare_button` (components::style).
4. `Div::paint` returns early when invisible/opacity 0 and takes deferred
   popups with it: never hide an open menu's trigger.
5. A scroller needs a definite height. Make the page root the scroller, not
   a `flex_1 min_h_0` child two levels down (that measured a scroll range of 0).
6. `cx.notify()` on any entity marks every ancestor dirty: the whole window
   re-renders. `render` must be cheap: derive in observers, never in render.
   No sorting, cloning of collections, or `format!` of N items per frame.
7. `window.request_animation_frame()` from render = full-window re-render at
   refresh rate. Only while something is actually moving.
8. Every list that can exceed ~50 rows is a `uniform_list`; grids virtualize by
   band (see `page_albums/src/grid.rs`).
9. Scrollers call `components::scroll::smooth` / `smooth_list` for the glide.
10. Decoded covers are swept by `store::Residents`; anything new that holds
    images goes through `store::artwork_source`, never raw `img(url)`.
11. `on_hover` needs a stateful element (`.id(..)`).
12. Bindings beat key listeners: a global single-key binding must decline
    (`cx.propagate()`) when something else holds focus.

**Instrument what you build:** `let _t = profile::render("name");` at the top
of any page-level `render`. The heartbeat reports the four most expensive views.

## 1. Action registry: the spine  ·  new crate `commands`

Every verb in the app becomes a registered command. Menus, the palette,
keybindings and the shortcuts sheet are all projections of one list. This also
kills a standing defect at its root: the same track has four different menus
today because each surface hand-rolls its own.

```rust
pub struct Command {
    pub id: &'static str,            // "track.play_next"
    pub label: fn(&App) -> SharedString,   // i18n key lookup
    pub icon: Option<&'static str>,
    pub group: Group,                // Playback, Queue, Library, Navigate, View, App
    pub keys: &'static [&'static str],     // default bindings
    pub danger: bool,                // paints in theme.danger, confirms first
    pub available: fn(&Target, &App) -> bool,
    pub run: fn(Target, &mut Window, &mut App),
}
pub enum Target { None, Track(Vec<String>), Album(String), Artist(..), Playlist(String), QueueItem(u32), Source(String) }
```

- `commands::menu(target, cx) -> PopupMenu builder`: the ONE way a context
  or dots menu is built. Same items, same order, everywhere. Capability gating
  lives in `available`, not at call sites.
- `commands::for_palette(target, cx)`: what the palette lists.
- `commands::keymap(cx)`: registers every binding; conflicts are a test
  failure, not a runtime surprise.
- Migrate: `components/track_list.rs::row_menu`, `page_home/cards.rs` menu,
  `fullscreen/player.rs` menu, `player_bar` menu, album/playlist/artist card
  menus. Delete the hand-rolled ones. Right-click works on every card that has
  a dots menu (today it works on some).
- `danger` commands always go through `components::dialogs::confirm_delete`.
- Tests: no duplicate ids, no duplicate default keys within a context, every
  label key exists in `en.ftl`.

Default keymap (context-scoped; all rebindable later):
`space` play/pause · `ctrl-right/left` next/prev · `right/left` seek ±5s (when
no list has focus) · `ctrl-up/down` volume · `m` mute · `l` lyrics · `q` queue ·
`f` fullscreen player · `ctrl-m` mini player · `ctrl-k` palette · `/` filter
current view · `alt-left/right` back/forward · `ctrl-1..4` destinations ·
`?` shortcuts sheet · `ctrl-,` settings · `delete` remove (queue/playlist) ·
`ctrl-d` favorite · `enter` play · `shift-enter` play next · `ctrl-enter` add
to queue.

## 2. Command palette  ·  owns `quick_search` (rename crate → `palette`)

`ctrl-k` stops being track search and becomes the app's front door.

- Modes by prefix, no prefix = everything: `>` commands, `@` artists,
  `#` albums, `:` playlists, plain text = tracks + everything ranked.
- Sections: *Current track* actions first when something is playing, then
  matches, then *Navigate*, then *Settings* (every setting is reachable by
  name; selecting one opens Settings scrolled to and highlighting that row).
- Each row shows its keybinding on the right (`Kbd`). This is how shortcuts
  get learned.
- Arrow keys wrap; the highlighted row is always scrolled into view (open
  defect today: highlight walks off-screen). `tab` on a track row drills into
  that track's actions.
- Recent commands and recent searches when the input is empty.
- Fuzzy matching, client-side, over already-loaded data; daemon search for
  tracks is debounced 150ms. Never blank the list while a query is in flight;
  keep the previous results dimmed.

## 3. Navigation: the sidebar goes, a top bar replaces it  ·  owns `sidebar` (becomes `topbar` + `playlists_panel`), `app/router.rs`, `app/shell.rs` layout, `store/nav.rs`

The v1 sidebar is a static twelve-link menu in a permanent 190px column that is
more than half empty, holds nothing of the user's, and costs a fifth of a tiled
900px window. Four destinations do not justify a column.

**Destinations:** Home · Library · Discover (absorbs Search landing + Genres) ·
Radio.

**Top bar (~44px, full width):**
`[back][forward]` · the four destinations as tabs (`ctrl-1..4`, active one
underlined in the accent) · a centred search field that opens the palette and
shows its `ctrl-k` hint · `[activity indicator (§7)] [source switcher]
[settings gear]` on the right. Below ~700px the tab labels collapse to icons.

- Back/forward are disabled when empty (`can_go_back` exists and is unused;
  `go_forward` has no caller); mouse buttons 4/5 bound. No page draws its own
  back chevron any more: `PageHeader::back` goes away.
- **Favorites** is a filter chip in Library, not a page.
- **Activity / Downloader / jobs** are status popovers (§7), not places.
- **Playlists panel** (left, optional, `ctrl-b`): pinned playlists and folders
  as a list: click opens, tracks/albums drop onto one to add, drag to reorder,
  right-click gets the §1 menu. It is content, which is what earns a column.
  Same drag-resize and width persistence as the right-hand queue panel; closed
  by default below ~1100px window width; its open state persists.
- Everything in the bar and the panel is keyboard reachable: focus handles,
  `tab_index`, roving arrows within the tab strip and the panel list, enter
  activates, visible focus ring.
- Content caps its own width: the track table stops stretching past ~1400px
  (title-to-artist gap is 400px on a 2000px window today); grids centre.
- Routes keep their params; old routes (`Route::Favorites`, `Activity`, …)
  redirect to the new home of that content so nothing 404s.
- Window state persists across launches: size, playlists panel width and open state, side
  panel width, last route, per-route scroll offset. Store in the fork's own
  state file, not in daemon config.

## 4. Library: one view, not four pages  ·  new crate `page_library2` replaces `page_library`, `page_albums` grid, `page_artists` grid, `page_playlists` page, `page_favorites`

One page. A facet switch (Tracks / Albums / Artists / Playlists) changes the
presentation; everything else is shared.

- **Filter bar:** type-to-filter (focus with `/`), chips for Favorites,
  Downloaded, Genre, Year range, Source folder. Chips compose. The active
  filter set is in the route, so back/forward and restart restore it.
- **Tracks** is a real table: sortable column headers with direction glyphs
  (open defect: Library's header looks sortable and is inert), resizable and
  reorderable columns, show/hide columns via header right-click, density
  setting (compact 32px / comfortable 56px). Column layout persists.
- **Albums / Artists / Playlists** are the virtualized band grids, with a
  list-mode toggle, an **alphabet jump rail** on the right edge, and
  **type-ahead**: typing letters with the grid focused jumps to the first match.
- **Group by** (tracks facet): none / album / artist / year, with sticky
  group headers.
- **Paging, finally:** fetch `Page{offset,limit}` for the visible window and
  extend on scroll (`store::all()` = `u32::MAX` dies here). The
  `UniformListScrollHandle` knows the visible range. First paint must not wait
  for the whole library.
- Selection model from `TrackList` (ctrl/shift-click, arrows, ctrl-a, escape)
  extends to grids. A selection bar appears with the §1 commands for that
  target; it never shows "0 selected".
- Every tile and row marks what is currently playing (open defect: grids
  don't). Drag sources everywhere: tracks, albums (drags its tracks), to queue,
  to pinned playlists.
- Detail pages (album, artist, playlist) stay as routes but share one
  `DetailHeader` widget: cover, title, meta line, primary actions from §1.
  Playlist detail gains its missing loading/empty states and column header.
- Empty states always say what to do next and carry the button that does it
  ("Add a music folder" → Settings/Library; "Sign in" → the source's sign-in).
  `Favorites`' three-state empty is the model. Failed reads render an error
  state with Retry, never "nothing here" (`Query::error()` exists).
- Skeleton rows/tiles instead of a centred spinner; `set_fetch` must keep the
  previous value dimmed instead of blanking (open defect in `store/query.rs`).

## 5. One player, three sizes  ·  new crate `now_playing` replaces `player_bar`, `fullscreen`, side_panel's role

Today: bar, fullscreen, mini, side panel: four implementations. Fullscreen's
queue and lyrics are stripped copies of the side panel's good ones.

- One `NowPlaying` entity; three presentations of the same parts:
  **bar** (bottom, always) → **sheet** (slides up over the page, the
  "fullscreen") → **mini** (a real second OS window, always-on-top, ~380×148,
  via GPUI multi-window, not the main window resized. Closes the open defect
  where compact mode leaves a 1350×800 "mini" player).
- The bar→sheet transition is one motion: the cover grows from its bar slot to
  the hero position (tween position+size with `motion::length`), the page
  dims beneath. Reduced-motion: cross-fade.
- **Parts, written once:** `Transport`, `SeekBar`, `Volume`, `TrackMeta`,
  `QueueView`, `LyricsView`. The side panel and the sheet embed the same
  `QueueView`/`LyricsView` (synced follow, click-to-seek, karaoke fill, drag
  reorder, remove, all of it, everywhere).
- **SeekBar:** hover shows the target time in a tooltip that follows the
  pointer; dragging shows it live; the clock updates while scrubbing in every
  presentation; respects `NowPlaying.seekable`; hit area ≥ 16px tall even when
  the paint is 3px; buffered ranges painted.
- **Clocks:** tabular/monospace digits so they stop jittering; click the right
  clock to toggle total ↔ remaining; widen past one hour.
- **Volume:** perceptual curve at the UI edge (cubic; wire value stays
  linear); scroll scales with delta magnitude and accumulates sub-steps (open
  defect: a trackpad flick slams 0→100); mute lives on `PlayerModel` (done).
- **"Playing from"**: a link under the title naming the album/playlist/
  search the queue came from; click goes there.
- **Queue:** sections *History* (collapsed) · *Now* · *Next up*; clear
  upcoming; shuffle upcoming; save queue as playlist; undo for remove/clear;
  optimistic moves recompute `position` locally and roll back on failure (open
  defect: fire-and-forget edits drift from the daemon).
- **Errors:** a failed command clears `optimistic_playing` and toasts; the
  play glyph never lies.
- Long titles: marquee on hover in the bar, tooltip everywhere.
- **Sleep timer** and **playback speed** (if the daemon grows them) slot into
  Transport's overflow menu; design the slot now.

## 6. Artwork-driven colour  ·  owns `theme`, small hook in `now_playing`

- Extract a palette from the playing cover (dominant + vibrant; do it off the
  UI thread on the already-decoded thumbnail, cache by `ArtworkRef.version`).
- Use it for: the sheet's background wash, the seek bar fill, the playing-row
  tint, focus accents. Never for text without a contrast check: clamp
  lightness until WCAG AA holds against the theme's background.
- Tween the accent over ~600ms on track change (`motion::color_over`).
- A setting: *Accent from artwork*: on / sheet only / off. Themes stay the
  base; this only moves the accent.
- Contrast audit of all 25 built-in palettes while in there; fix any pairing
  that fails AA for body text.

## 7. Status lives in the chrome  ·  owns `overlays`, new popovers in `now_playing`'s bar slot

- **Activity popover** (bar, right side): running jobs with progress and a
  Stop that shows *Stopping…* until the job leaves (open defect); scan can be
  cancelled like downloads can; finished jobs linger 5s with their outcome.
- **Downloads popover:** the queue, per-track state, retry failed. When a
  batch ends: a summary toast ("38 downloaded, 2 failed · View") and the
  failed rows stay reachable (open defect: they vanish with the card).
- **Notification centre:** toasts are also appended to a history list behind a
  bell; errors do not auto-dismiss; identical messages replace rather than
  stack (derive the notification id from the message).
- **Connection state** in the chrome, not only on a full-screen takeover:
  a slim banner "Reconnecting… (attempt 3) · Retry now" while the page stays
  visible and dimmed. App never quits without a window: a bad
  `KOPUZ_DAEMON_ADDR` lands on the connection screen with the reason
  (open defect: `cx.quit()` before any window exists).
- "Start Daemon" shows *Starting…* and disables until the next status change.
- Undo toasts: removing from queue/playlist, clearing the queue, unfavoriting a
  selection: `Undo` for 6s. Deletes from disk confirm instead (not undoable).

## 8. Keyboard and focus, app-wide  ·  owns `components` focus helpers; touches every crate lightly, run LAST among UI packages

- Every hand-built interactive row gets a focus handle + `tab_index` + a
  visible focus ring: top bar tabs, playlists panel rows, settings category tabs, source switcher rows,
  palette rows, cards. `grep tab_index` must stop returning zero.
- A `components::focus::Roving` helper: one tab stop per group, arrows move
  within (tab strips, panel lists, card grids, segmented controls).
- The source switcher becomes a `PopupMenu` (gets escape/arrows/enter free).
- Hover-only affordances also reveal on focus-within; dots buttons rest at low
  opacity instead of invisible.
- Escape is one chain, innermost first: palette → popover/menu → dialog →
  selection → sheet → side panel.
- Dialogs: first field focused on open, Enter submits, backdrop never discards
  typed text, dirty forms confirm before closing (theme editor included:
  switching themes mid-edit asks first, and shows a modified dot).
- `?` opens the shortcuts sheet, generated from §1.
- Tooltips on icon-only buttons name the action **and its key**.

## 9. Settings that explain themselves  ·  owns `page_settings`, `settings_*`

- A search box at the top: filters rows across every category live.
- Every non-obvious row gets a one-line description (`SettingRow::description`
  exists and is used once). Locked rows explain *why* on hover ("Managed by
  your system configuration").
- Section headers either collapse (as upstream) or lose their hover.
- Lift the three duplicated `row.rs` copies into `components::settings`.
- A quiet "Saved" tick near the control after the debounced write lands;
  failed writes toast and revert the control. If the config never loaded, the
  page says so instead of rendering dead controls.
- Schema forms: honour `custom: true` choices (free-text entry, needed for
  Apple Music storefronts); `Radio` renders as a radio group; `Note` renders as
  a paragraph, not a bold empty label; stored secrets show "saved ••••" so
  blank no longer means two things; per-field validation messages attach to
  the field, including the server *name* field (open defect).
- Metadata editor: unparseable numbers flag the field inline and block save;
  Save shows in-flight state; a failed save stays in the editor with the
  reason; batch edit for a multi-selection (album/artist/year/genre).
- Sign-in rows show "Waiting for your browser…" with a spinner while the
  daemon runs the browser flow, and confirm success with a toast.

## 10. First run  ·  new crate `onboarding`

Empty daemon, no sources: today you land on a Home made of empty shelves.
- A three-step first-run: pick a source type (Local folder / Server / Streaming
  service) → configure (reuses the real forms) → first scan/sync with live
  progress, then land in Library.
- Dismissible; never shown again once any source has content.

## 11. Home worth opening  ·  owns `page_home`

- Lead with *Jump back in* (recent albums/playlists, big tiles) and *Continue*
  (the interrupted queue). Shelves below.
- Horizontal shelves glide on wheel (extend `components::scroll` to the X axis),
  snap to tile edges, show edge fades, arrows appear on hover/focus.
- Card menus come from §1; every card right-clicks.
- `Query` must not notify on loading-start while it holds a value: one
  invalidation currently triggers ~10 `rebuild()`s on Home.

## 12. Performance floor  ·  owns `store`, `profile`

- Paging (§4) is the big one. Then: `QueueModel` summary cached on change;
  artist detail stops rebuilding an all-artists photo map per render;
  playlists page stops deep-cloning every `track_keys` per frame; tuple
  `ElementId`s instead of `format!` for motion ids in hot rows.
- Per-view render timing already reports; add counters for notifies/second and
  elements built per frame. A debug overlay (`ctrl-shift-p`) showing rebuilds/s,
  worst view, covers live, allocated MB.
- Stop the 250ms playhead tick when the window is not visible.
- Budget: any view's `render` over 2ms at 2.5k albums is a bug; the heartbeat
  line is the evidence.

## 13. Skins  ·  LAST

The `Skin` enum becomes a trait registry (Normal + room for Vaxry and
others): a skin supplies metrics (radii, row height, density), chrome
variants and optional asset overrides; palettes stay orthogonal. Nothing above
may hardcode what a skin would want to vary; go through `components::style`.

## Dependency graph and how to fan out

```
Wave 1 (parallel):  §1 commands · §6 colour · §9 settings · §10 onboarding · §12 perf
Wave 2 (parallel, needs §1):  §2 palette · §3 navigation · §5 now_playing · §7 status
Wave 3 (needs §3 + §1):  §4 library · §11 home
Wave 4:  §8 keyboard/focus sweep (touches everything; run alone)
Wave 5:  §13 skins
```

Ownership is by crate, so no two agents in a wave share a file. Where a
package needs a seam in a crate it does not own (`store`, `components`), the
agent adds it additively and lists it in its report; it never edits another
package's crate. New shared helpers go in `components` (UI) or `store` (state),
never copied per crate: three private copies of a helper is how the
hover-tracking code multiplied last time.

Each agent's report must list: what it built, which seams it added to shared
crates, any i18n keys added (in all 28 files), what it left undone and why,
and the gate output.
